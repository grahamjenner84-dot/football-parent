Generated by `npx tsx scripts/seo/cli/sandbox-integration-test.ts`.

## Result: 10/10 checks passed

Credentials in `.env.local` were fixed (password rotated) after an initial
HTTP 401 blocked the first attempt at this report. Two real bugs were then
found and fixed against the live sandbox response data itself (not
guessed):

1. **`backlinks/domain_intersection` and `page_intersection`**: the
   `targets` field is an object with sequential numeric-string keys mapping
   to plain domain strings (`{"1": "domain-a.com", "2": "domain-b.com"}`),
   not `{domain: {}}` as first implemented. The sandbox returned
   `"Invalid Field: 'targets'"` (status 40501), which pointed straight at
   it. Fixed in `scripts/seo/dataforseo/endpoints/backlinks.ts`.
2. **`task_get` for task-based endpoints** (`google_trends/explore`,
   `app_data/*`) must be called with **HTTP GET, no body** - it was being
   POSTed like every other call. Fixed generically in
   `scripts/seo/dataforseo/client.ts`'s `fetchDataForSeo`, so it also
   applies to the App Data task-based endpoints, not just Trends.

Both fixes are structural (request construction), not response parsing, so
they carry over correctly to live calls once those are approved - nothing
about them is sandbox-specific.
